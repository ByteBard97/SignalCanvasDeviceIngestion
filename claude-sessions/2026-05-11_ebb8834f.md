## 2026-05-13 — Per-stage worker architecture

Implemented the per-stage worker architecture in `runner.py`. The prior `asyncio.gather` loop was a snapshot-and-sync pattern: it built node lists at the top of each iteration, ran all stages concurrently, then waited for ALL to finish before looping again. This meant device A couldn't advance to Stage 2 until every other device finished Stage 1 — the same serial bottleneck, just shifted to the gather boundary.

The fix: replaced the loop body with 8 independent coroutines (`_stage_0_worker` through `_stage_67_worker` + `_completion_checker`), each running an infinite poll loop against the DB. Workers sleep briefly when idle. A `stop_event` signals all workers to exit when the pipeline is done or the hard cap is hit. The top-level `gather` has `return_exceptions=True` so one stage crash doesn't kill the others.

Extracted 5 query functions (`_query_stage_0_nodes`, etc.) from the old snapshot block — these are called by the workers on each iteration.

Key fixes bundled:
- `return_exceptions=True` on the final gather (previously absent)
- Stage 1b is now a continuous worker (was ad-hoc inside the loop)
- Each stage caps its batch size (`MAX_CONCURRENT_STAGE_1`, etc.) to prevent N tasks from all firing simultaneously on a big backlog
